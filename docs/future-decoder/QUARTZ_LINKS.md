# Ссылки между материалами в Quartz

Версия: 1.0 · 11 ноября 2026

Эти правила относятся к существующему репозиторию ereminaolyastrateg-stack/futuredecoder, ветке v5 и каталогу content. Шаблоны находятся вне content. Текущий черновик образовательных сигналов находится в ветке codex/education-signals-2026-11-11, PR #17.

## 1. Постоянный адрес сигнала внутри общего файла

Существующий файл: content/signals/education.md.

У каждого сигнала отдельный заголовок:

~~~markdown
## SIG-EDU-005

**TUMO Path: алгоритм собирает персональный маршрут из выбранных человеком областей**
~~~

Название можно уточнять, заголовок SIG-EDU-005 и путь исходного файла сохраняются. Обычный HTML-якорь этого заголовка — sig-edu-005.

Для новых тематических обзоров выбирать уникальный префикс номера. Один и тот же сигнал, повторно упомянутый в следующем обзоре, сохраняет исходный номер и адрес; новое издание может ссылаться на него.

## 2. Внутренние ссылки на страницах сада

Quartz в этом проекте поддерживает wikilinks и переходы к заголовкам. В теле публикуемой карточки можно использовать ссылку от корня content:

~~~markdown
[[signals/education#SIG-EDU-005|TUMO Path]]
~~~

В такую ссылку не включаются content/, ветка GitHub, blob/v5 или домен сайта. Это ссылка внутри сада, а не адрес исходного кода.

Если нужно показать весь раздел сигнала на другой странице, Quartz поддерживает включение раздела:

~~~markdown
![[signals/education#SIG-EDU-005]]
~~~

Включение полезно, когда читателю действительно нужен полный раздел. Для короткого списка свидетельств обычно достаточно названия, одной поясняющей фразы и ссылки.

Пример в этом документе показывает синтаксис. Он не является утверждением о содержании ещё не разобранной игры.

## 3. Обычные Markdown-ссылки

В GitHub и Quartz удобно использовать относительные ссылки с .md и якорем. Отсчёт — от файла, в котором находится ссылка.

Примеры предполагаемых новых путей ниже не означают, что все карточки уже существуют.

| Где находится ссылка | Относительная ссылка на SIG-EDU-005 |
|---|---|
| content/games/GAME-ID.md | `[TUMO Path](../signals/education.md#sig-edu-005)` |
| content/scenarios/cs.md | `[TUMO Path](../signals/education.md#sig-edu-005)` |
| content/macrotrends/mt-044/index.md | `[TUMO Path](../../signals/education.md#sig-edu-005)` |
| content/macrotrends/mt-044/cs.md | `[TUMO Path](../../signals/education.md#sig-edu-005)` |
| content/spheres/sph-01/cs.md | `[TUMO Path](../../signals/education.md#sig-edu-005)` |
| content/mediateka/knigi/BOOK-SLUG.md | `[TUMO Path](../../signals/education.md#sig-edu-005)` |
| content/mediateka/filmy/FILM-SLUG.md | `[TUMO Path](../../signals/education.md#sig-edu-005)` |

Адреса в правой колонке — буквальные примеры для файлов, перечисленных слева. В этом документе они показаны как код, чтобы не создавать ссылки на ещё не существующие карточки.

В Markdown-таблицах предпочтительны обычные Markdown-ссылки. Вертикальная черта в wikilink с подписью конфликтует с разделителем таблицы: если используется wikilink, черту необходимо экранировать. Вне таблиц можно свободно использовать wikilink.

## 4. Ссылка на вывод игры

Для конкретного опубликованного вывода сохранять глобально уникальный заголовок:

~~~markdown
## OBS-GAME-2026-XX-XX-A-001
~~~

Из карточки макротренда, сферы или медиатеки ссылка ведёт на соответствующий раздел карточки игры:

~~~markdown
[[games/GAME-2026-XX-XX-A#OBS-GAME-2026-XX-XX-A-001|Обсуждение на игре]]
~~~

Это только схема имени. Дату и номер заменить установленными значениями; неизвестную дату не выдумывать.

В рабочем разборе Observation ID имеет подробную запись с источником. В публичной карточке игры тот же ID должен реально присутствовать в заголовке с подходящим для публикации содержанием. Ссылка на несуществующий публичный заголовок не заменяет ссылку на рабочий разбор.

Если запись пока существует только в рабочем документе, сохранять её ID и источник в плане обновления. Публичную внутреннюю ссылку добавлять, когда целевой раздел создан.

## 5. Пути и ID

| Тип | ID / ссылка | Правило |
|---|---|---|
| Сигнал | SIG-EDU-005 + signals/education.md#sig-edu-005 | Один текст в обзоре; постоянный заголовок |
| Макротренд | MT-044 | Точный ID из базы; сначала найти существующий путь |
| Сценарий | ЦС / ЦЗ / ДС / ДЗ | Для новых имён файлов допустимы cs / cz / ds / dz |
| Сфера | Точное авторское название и имеющийся ID | Не придумывать названия восьми сфер по теме одной игры |
| Книга / фильм | Существующий путь в mediateka | Проверить название, автора, тип произведения и версию до создания дубля |
| Игра | Постоянный game_id | Дата игры хранится отдельно и не угадывается |
| Вывод | OBS- + game_id + номер | Глобально уникальный; сохраняется при редактировании |

Новые пути предлагаются в плане обновления, после проверки существующих файлов. Существующие адреса не переименовываются только ради новой схемы.

## 6. Явные переходы и обратные ссылки

Для каждой содержательной связи:

1. В карточке макротренда или сферы сослаться на конкретный сигнал и соответствующий вывод игры.
2. В карточке игры перечислить обновлённые макротренды, сферы и произведения.
3. В медиатеке указать конкретное обсуждение игры и его содержательные связи.
4. В разделе сигнала «Обсуждения и связи» по мере появления добавлять ссылки на использующие его карточки и игры.

Ссылку добавлять, когда связь имеет содержательное объяснение. Совпадение темы не является достаточным основанием.

Простой ID в YAML или слово-хэштег не создают автоматически все эти переходы. Для кликабельной связи и обычного графа нужна настоящая ссылка в тексте.

Стандартные теги, граф и обратные ссылки Quartz работают прежде всего со страницами. Отдельные заголовки сигналов не становятся самостоятельными узлами графа по одному факту появления номера.

Автоматические списки отдельных сигналов по макротренду, сфере, стране или тегу потребуют отдельного указателя сигналов при сборке сайта. Этот комплект шаблонов такую функцию не устанавливает. До её появления используем явные ссылки и проверяем их.

## 7. Публикация и доступность ссылок

Восстановленный education.md сейчас имеет draft: true. Файл существует в черновой ветке, но это не означает, что соответствующий адрес уже доступен на сайте.

Чтобы опубликованный переход работал:
- оба нужных файла должны попасть в публикуемую версию;
- целевой файл не должен быть исключён из сборки как черновик или другим правилом;
- якорь должен существовать в целевой странице;
- ссылка должна быть рассчитана для конечного расположения карточки;
- номер и регистр/нормализация якоря должны быть проверены.

Шаблоны с незаполненными полями остаются рабочими документами. Готовность к публикации оценивается отдельно от наличия файла в GitHub.

## 8. Проверка перед завершением обновления

- Проверить существование всех внутренних целевых файлов.
- Проверить заголовки после символа #.
- Проверить переход из карточки в конкретный сигнал, а не только в обзор.
- Проверить переход из медиатеки в соответствующее обсуждение игры.
- Проверить, что одна запись не размножена под разными ID.
- Проверить существующие ссылки после любого перемещения.
- Проверить опубликованную сборку при публикации; если проверена только структура исходников, так и указать.
